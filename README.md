# X AI 回复助手

在 X（Twitter）推文时间线点击**回复气泡**打开发帖弹层时，扩展会自动读取被回复的推文内容，调用 AI 生成**多条**回复候选，点击任一条即可一键回填到输入框。

纯前端 Chrome 扩展（Manifest V3），无需服务器；API Key 只存在本地 `chrome.storage.local`，请求由浏览器直接发往你选定的模型服务商。

![面板预览](dev/preview-panel.png)

## 功能

| 能力 | 说明 |
|---|---|
| 自动识别弹层 | 侦测 X 的回复发帖弹层（多选择器容错，X 改版不易崩） |
| 提取推文内容 | 作者、handle、正文、发布时间、媒体类型；纯媒体推文也能识别 |
| 多条候选 | 一次生成 1–5 条，各自风格不同，不是同一句话改写 |
| **提示词可配置** | **system / user 模板完全自定义，12 个 `{{变量}}` 插值 + 实时预览** |
| **流式输出** | **边生成边显示，网络慢时第一个字约 1 秒可见** |
| **面板可拖拽** | 标题栏按住拖动，自动锁定位置；双击复位 |
| 8 种风格 | 幽默 / 专业 / 犀利 / 共情 / 争议 / 抽象 / 翻译润色 / 嘲讽 |
| 一键回填 | 点候选即写入 Draft.js 编辑器，**字符计数与发帖按钮正常联动** |
| 长耗时反馈 | 生成中显示实时计时 + 首字延迟；超 30 秒出现进度条；随时可「中止」 |
| 失败可重试 | 报错后按钮变「↻ 重试」且保持可点，不会变成死按钮 |
| 不遮挡弹层 | 面板优先贴在弹层左侧，保证随时能看到输入框和发帖按钮 |
| 时间线悬浮按钮 | 鼠标悬停推文时出现「✦ AI 回复」，不点回复气泡也能用 |
| 多服务商 | 智谱 GLM / DeepSeek / OpenAI / Claude / Kimi / OpenRouter / 自定义（Ollama、vLLM 等） |

### 快捷键

- `Ctrl / ⌘ + Enter` — 生成回复
- `Esc` — 关闭面板
- 候选卡片上有「复制」按钮，点一下即复制该条

## 网络慢 / 挂 VPN 变慢怎么办

按性价比排序，**先做第 1 条**，大多数情况就够了。

### 1. 保持「流式输出」开启（默认已开）

非流式要等模型把 N 条**全部生成完**才显示第一个字；流式下第一条约 1 秒就出现，后面陆续补齐。
网络越慢，这个差距越明显 —— 状态栏会显示「首字 x.x s」，可据此判断网络质量。

### 2. 测速对比，再决定要不要改代理

设置页 **2 · 网络与代理** → 点 **「测速对比」**，会分别测：

| 测项 | 含义 |
|---|---|
| 当前网络设置 | 走浏览器/系统默认（VPN 生效时走这条） |
| AI 接口直连 | 绕过代理，直连 AI 接口 |

数字小的是快的。测速**只影响 AI 接口这一个域名**，你正在看的其他网站不受影响。

![网络设置卡片](dev/preview-net-card.png)

### 3. 代理模式怎么选

| 模式 | 影响范围 | 说明 |
|---|---|---|
| **跟随系统默认** | 不改任何设置 | 默认。VPN 在系统层生效时本来就在走它，**多数人不需要动** |
| **AI 走直连，其他仍走代理** | 仅 AI 接口域名 | 填你原本在用的代理地址，扩展只把 AI 域名绕过。**最精准，推荐** |
| **全局直连** | ⚠️ 整个浏览器 | 会关掉你**所有标签页**的代理，其他网站可能打不开。需二次确认 |

> ⚠️ **为什么只能这么设计**：浏览器 `fetch()` **无法为单个请求指定代理**，没有 proxy 选项。
> 要指定代理只能通过 `chrome.proxy` 改**浏览器全局**规则。所以「全局直连」确实会波及整个浏览器 ——
> 这正是提供「AI 走直连，其他仍走代理」这个模式的原因：它借 `bypassList` 精准只绕过 AI 域名。
>
> 扩展不会偷偷改你的代理：模式是 `auto` 时它什么都不碰；`direct` / `custom` 都会弹确认并明确告知影响范围。
> 点「恢复默认」随时交还控制权。停用插件或重启浏览器时，扩展也会自动清理自己设的规则。

## 面板操作

- **拖拽**：按住标题栏（带 `⠿` 图标那行）即可拖动。拖过后面板会**锁定在你放的位置**，不再随弹层自动跟随。

## 安装

```
1. 打开 chrome://extensions/
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本项目根目录（含 manifest.json 的那层）
```

首次安装会自动打开设置页。

### 配置

1. 点扩展图标 →「全部设置」
2. 「快速预设」选服务商（如智谱 GLM），Base URL 和模型名会自动填好
3. 填 **API Key**
4. 点 **「测试连接」** —— 返回示例即表示配置正确
5. 关掉设置页，去 X 上点回复气泡即可

> ⚠️ **max_tokens 别调太小。** 推理型模型（GLM 全系 / o 系列 / Claude 思考版）会先消耗 reasoning tokens 再输出正文，
> 给小了会出现「请求成功、正文却是空字符串」且**不报错**的现象。低于 2000 极易踩坑，本项目默认 4000。

### 升级已安装的扩展

改了代码或重新下载后，需要在 `chrome://extensions/` 点扩展卡片上的**刷新按钮**，然后**刷新 X 页面**。
不刷新的话浏览器还在用缓存的旧脚本。

## 提示词配置

设置页 **4 · 提示词**，三层可配置，**留空即用内置默认**（推荐）：

| 层级 | 作用 |
|---|---|
| **人设 / 背景** | 插在 system prompt 最前，长期定义 AI 身份与语气 |
| **全局补充要求** | 替换模板里的 `{{customInstruction}}`，每次生成都带上 |
| **System / User 模板** | 完全接管，用 `{{变量}}` 占位 |

### 可用变量（12 个）

设置页点一下变量标签即可插入到光标处，拼错会实时警告。

| 变量 | 含义 | 变量 | 含义 |
|---|---|---|---|
| `tweet.text` | 推文正文 | `count` | 生成条数 |
| `tweet.author` | 作者昵称 | `style` | 风格描述（含详细提示） |
| `tweet.handle` | 作者 handle | `styleName` | 风格名（如「幽默」） |
| `tweet.time` | 发布时间 | `length` | 长度描述 |
| `tweet.media` | 媒体类型 | `lang` | 输出语言 |
| `tweet.url` | 推文链接 | `customInstruction` | 补充要求 |

### 输出格式约束

- **严格 JSON 数组**（默认，最稳）—— 扩展用括号配平扫描解析，多层兜底
- **自由文本** —— 模型按 `1. 2. 3.` 编号输出，自定义风格时更自由

### 示例：只要干货，不要情绪

```text
System:
你是一个技术社区的资深工程师，回复要专业、克制、有信息量。
风格：{{style}}
条数：{{count}}
语言：{{lang}}
不要使用 emoji，不要感叹号。

User:
以下是一条推文：
{{tweet.text}}

请写 {{count}} 条回复，每条都要有一个具体的观点或事实。
```

配「输出格式约束 = 自由文本」效果更好。

### 实时预览

点「预览渲染结果」会**用示例推文渲染完整提示词**（system + user 分开展示），**不消耗 API 额度**。
改完模板先预览再保存，可以直接看到模型会收到什么。

> 预览与实际发送共用 `src/shared/prompt.js` 同一份逻辑，所见即所得。

## 关键实现说明

### 为什么 AI 调用放在 service worker

content script 的 `fetch` 受页面 CSP 与同源策略限制，无法直连模型服务商。放到 background 后：

- 不受 X 页面 CSP 约束
- API Key 不会暴露给页面 JS（content script 与页面是隔离世界）
- 可统一做超时控制与中止（`AbortController`）

### 回填编辑器为什么这么写

X 的发帖框是 **React 控制的 contenteditable（Draft.js）**。直接 `el.innerHTML = x` 或 `el.textContent = x` 会出现一个极具迷惑性的现象：

> **文字显示出来了，但字符计数不动、发帖按钮还是灰色。**

因为 React 的 state 并不知道内容变了。正确做法（见 `src/content/editor.js`）：

1. `focus()` 编辑器
2. 用 `Range` 选中全部内容 + `execCommand('delete')` 清空（走浏览器原生编辑路径，Draft 能正确收到）
3. 用 **`HTMLElement.prototype` 的原生 `textContent` setter** 写入，绕过 React 的劫持
4. 派发 `input`（`inputType: 'insertText'`）+ `change` 事件，让 Draft 更新 state
5. 写入后回读校验，不一致则重试一次

### 模型输出解析为什么要做四层兜底

真实模型很少严格只吐一个 JSON 数组。`utils.parseReplyList` 依次尝试：

1. 整体就是 JSON 数组
2. 用**括号配平扫描**（带字符串转义感知）从长文本里抠出数组
3. 匹配 ` ```json ` 代码块
4. 退化：按换行 / `1.` `-` 编号列表切分

> 注意不能用「第一个 `[` 到最后一个 `]`」——模型正文里出现「参考 [1] 说法」这类字样时会截错。
> 另外 `[1,2,3]` 这种**数字数组**不算数，必须只接受**字符串数组**。

### 流式输出怎么做的

content script 与 service worker 用 **Port 长连接**（`chrome.runtime.connect`）而非 sendMessage：

- SSE 按 `\n\n` 切事件，缓冲区跨 chunk 保留（半包很常见）
- `reasoning_content` / `thinking_delta` 单独统计，不混入正文
- 面板边收边 `parseReplyList`，**已生成完的几条可以先点先用**，未收完的显示「正在来」占位
- 面板关闭 / 点中止时主动 `disconnect`，service worker 侧立即 `abort`，不白烧 token

> 这两个工具就是专门抓它们的。

## 常见问题

**Q：点回复气泡，面板没出现？**
A：① 确认扩展图标不是灰的（popup 里开关是否打开）；② 刷新 X 页面（安装或升级扩展后需刷新一次）；③ 到设置页开「调试日志」看 Console。

**Q：控制台报 `Xxx is not a function`？**
A：八成是扩展没刷新，浏览器还在跑缓存的旧脚本。去 `chrome://extensions/` 点扩展卡片上的刷新按钮，再刷新 X 页面。

**Q：提示「找不到发帖弹层」？**
A：X 改版时选择器可能失效。打开设置 →「开启调试日志」，Console 里会打印探测结果；把新的 `data-testid` 补进 `src/content/detector.js` 的 `D.SEL` 即可。选择器都做了「多候选 + 容错」，通常不用改。

**Q：生成很慢？**
A：先确认「流式输出」是开启的（默认开）—— 流式下第一个字约 1 秒可见，状态栏会显示「首字 x.x s」。若仍然慢，点设置页的**「测速对比」**看是不是代理绕路导致的。另外推理模型本身慢，可把 GLM 的「关闭深度思考」勾上（默认已勾），或换 DeepSeek。

**Q：一定要在设置里配代理吗？**
A：多数情况不用。VPN 在系统层生效时，浏览器默认就会走它，扩展也跟着走。只有当测速显示「AI 接口直连」明显更快时，才需要改 —— 用 **「AI 走直连，其他仍走代理」**（填你原本的代理地址），它只影响 AI 接口域名，不动你其他网站。

**Q：插件会不会把我的代理关掉？**
A：**不会擅自关**。默认「跟随系统默认」模式下扩展完全不碰代理设置。只有你手动选了「全局直连」（会弹确认）才会关掉整个浏览器代理 —— 这正是我们不推荐它的原因。想精准控制请用「AI 走直连，其他仍走代理」。
另外：停用插件、切回默认、或重启浏览器时，扩展都会自动清理自己设的代理规则，不会残留霸占。

**Q：面板挡住弹层 / 想放别处？**
A：按住标题栏（带 `⠿` 那行）拖到任意位置，拖过后面板会锁定在那儿不再自动跟随。双击标题栏或点「复位」恢复自动定位。

**Q：点候选提示「发帖弹层未打开」？**
A：从时间线的悬浮按钮生成时还没有弹层，需要先点该推文的回复气泡打开弹层，再回来点候选。正常从回复气泡进入不会有这个问题。

**Q：自定义模板后 AI 不听话 / 解析不出多条？**
A：① 保持「输出格式约束 = 严格 JSON 数组」；② 检查模板里是否写了「只输出一条」之类的矛盾指令；③ 点「预览渲染结果」确认 `{{count}}` 正常替换成了你要的条数。

**Q：变量名写错了会怎样？**
A：设置页会实时红字警告。生成时未定义变量会被替换成**空串**——绝不会把 `{{xxx}}` 原文发给模型。

**Q：能把自己的账号人设写进去吗？**
A：能。用「人设 / 背景」字段，例如「我是一名后端工程师，说话直接，不爱客套，不用感叹号」——它会插在每次 system prompt 的最前面。

**Q：用本地 Ollama 报错？**
A：需要在 `chrome://extensions/` 里点扩展的「详细信息」→「网站访问权限」，把 `http://localhost/*` 加进去，否则跨域请求会被浏览器拦截。Base URL 填 `http://localhost:11434/v1`。

**Q：能改成别的模型吗？**
A：能，只要它兼容 OpenAI 的 `/chat/completions`。设置页「自定义（OpenAI 兼容）」填 Base URL 和模型名即可。
